# Темы, QuickCSS и плагины

Arachnid Client поддерживает расширения так же, как клиентские моды вроде
[Avia Client](https://github.com/AvaLilac/for-desktop) или Vencord: тема — это файл
CSS, плагин — файл JavaScript, который выполняется на странице веб-клиента.
Плагины и темы, написанные для Avia Client, работают без изменений.

Интерфейс по-прежнему официальный for-web: оболочка сама его не меняет, а
применяет только те темы и плагины, которые вы включили.

Устроено в три слоя, как у BetterDiscord и Vencord:

- **Ядро** — то, без чего клиент не работает как задумано: мост со страницей,
  разделы настроек, Twemoji по умолчанию, наборы эмодзи, темы и QuickCSS. Оно
  всегда включено; в разделе «Плагины» — строка с замком и версией API плагинов.
- **Встроенные плагины** — улучшения, которые не обязательны: их можно
  выключить, как любой плагин. Сейчас это «Quality of Life» — разделы и «Часто
  используемые» в окне выбора эмодзи. Включён, пока его не выключили.
- **Свои плагины и темы** — файлы (`.js`, `.css`, формат Avia Client) или
  папки с манифестом: у плагина-папки есть API `plugin` — настройки, хранилище,
  свои картинки и шрифты, сеть по разрешению и нативный модуль WebAssembly (см.
  «Плагины-папки» ниже).

## Где лежат файлы

Всё хранится в каталоге данных, рядом с `config.toml` (в portable-режиме это
папка с `arachnid-client.exe`):

```
Arachnid-Client/
├── themes/          темы: *.css или папки с theme.toml
├── plugins/         плагины: *.js или папки с plugin.toml
├── plugin-data/     хранилища плагинов-папок (пишет клиент)
├── quickcss.css     свой CSS, действует всегда
└── extensions.json  выбранная тема, настройки, включённые плагины и разрешения (пишет клиент)
```

Папки `themes/` и `plugins/` клиент создаёт сам при запуске.

## Настройки клиента

Расширения управляются прямо в настройках Stoat (шестерёнка):

- **Плагины.** Пункт в «Настройках клиента» между «Внешним видом» и
  «Уведомлениями» — там, где у самого for-web заготовлен (закомментирован)
  пункт plugins. Значок — тот же «extension», но из Material Symbols (этим
  набором for-web рисует и «ПК»): у старого варианта из Material Design Icons
  тело пазла сидит ниже соседних значков. В разделе версия клиента и ядра (с
  версией API плагинов), кнопка «Папка плагинов», список плагинов с
  переключателями — сначала встроенные, затем свои (название, автор, версия и
  описание берутся из комментария в начале файла или из `plugin.toml`). У
  плагина-папки с настройками — кнопка-шестерёнка (окно настроек), у
  плагина, которому нужен доступ в сеть, — окно разрешений при включении;
  плагин-папка с ошибкой в манифесте показывается с её текстом и не
  включается. Ниже — «Действия плагинов»,
  пункты, которые плагины добавили через `window.AviaMenu`. Включённый плагин
  запускается после перезагрузки страницы: раздел показывает это у плагина и
  предлагает кнопку «Перезагрузить». Вход при перезагрузке сохраняется.
- **Внешний вид → Тема.** Вместо приветствия «Welcome to the new appearance
  menu…» вверху «Внешнего вида» — кнопки «Папка тем» и «Изменить QuickCSS»
  (такие же, как «Папка плагинов» в «Плагинах»), под ними выбор темы:
  «Stoat (по умолчанию)» или любая тема из `themes/`. Встроенные палитры и
  «Цвета» Stoat относятся к стандартному оформлению, поэтому при выбранной сторонней теме вместо них показываются
  «Настройки темы» — палитры, цвета, переключатели и размеры, которые описала
  сама тема (см. «Настройки темы» ниже), и кнопка сброса. Остальные разделы
  «Внешнего вида» (текст, шрифты, отступы) работают с любой темой.
- **Редактор QuickCSS.** «Изменить QuickCSS» открывает окно поверх клиента —
  такое же, как диалоги Stoat; клиент за окном размыт. CSS пишется прямо в нём: номера строк, шрифт —
  моноширинный из «Внешнего вида», Tab и Shift+Tab сдвигают строку или
  выделенные строки, Enter сохраняет отступ (после `{` — на шаг глубже),
  Ctrl+Z отменяет. Через долю секунды после правки текст применяется к клиенту
  и сохраняется в `quickcss.css` (Ctrl+S — сразу), поэтому закрыть окно можно в
  любой момент: Esc, «Готово» или щелчком мимо. «Открыть в редакторе» —
  тот же файл в программе по умолчанию; правку, сохранённую там, окно
  подхватывает само, если в нём нет своих несохранённых изменений.
- **Подпись.** Внизу списка настроек вместо «Stoat for Desktop» написано
  «Arachnid Client» с версией клиента.

Изменения применяются сразу: тема, её настройки и QuickCSS — без перезагрузки,
выбор в настройках и в трее синхронизирован.

## Меню трея

То же доступно из меню значка в трее, раздел **«Расширения»**:

```
Расширения
├── Темы              ◉ Stoat (по умолчанию)
│                     ─────────
│                     ○ catppuccin-mocha.css
│                     ○ amoled.css
│                     ─────────
│                     Открыть папку
├── Плагины           ☑ Quality of Life
│                     ─────────
│                     ☑ Translate.js
│                     ☐ KlipyV2.js
│                     ☐ translator          (папка)
│                     ─────────
│                     Открыть папку
├── Изменить QuickCSS
├── ─────────
└── Действия плагинов   (появляется, когда плагины добавили свои пункты)
    ├── Set API Key
    └── Auto Capitalize ▸ Enabled
```

- **Темы.** Выбрана всегда одна тема или стандартное оформление Stoat; выбор
  сразу применяется. Повторный выбор той же темы возвращает стандартное
  оформление. Сохранённый файл темы применяется сразу, без перезагрузки:
  удобно править тему в редакторе. (До 0.14 темы включались флажками по
  нескольку; при обновлении выбранной становится первая включённая.)
- **QuickCSS.** «Изменить QuickCSS» показывает окно клиента с редактором
  QuickCSS (см. «Настройки клиента» выше). Файла `quickcss.css` до первой
  правки нет — редактор начинает с заготовки. QuickCSS подключается последним и
  перекрывает темы.
- **Плагины.** Флажок включает или выключает плагин и перезагружает страницу:
  выгрузить уже выполненный код нельзя. Вход при этом сохраняется. Плагин,
  который просит доступ в сеть и ещё не получил разрешения, в трее
  недоступен: его включают в настройках, где показано окно разрешений.
- **Новые файлы выключены.** Плагин, который вы положили в папку, не запустится,
  пока вы не включите его. Новые файлы появляются в меню и в настройках сами,
  перезапускать клиент не нужно.

На английской системе пункты называются Extensions, Themes, Plugins, Edit
QuickCSS и Plugin Actions.

## Как это работает

| Что | Как |
|---|---|
| Темы и QuickCSS | `bridge.js` держит по элементу `<style data-arachnid-style="…">` на выбранную тему и QuickCSS в конце документа, чтобы перекрывать стили клиента. При загрузке страницы стили запрашиваются командой `extensions_styles`, при сохранении файла или смене настроек темы Rust передаёт новые в `__arachnidDesktop.setStyles`. Значения настроек темы Rust подставляет в CSS сам (`usercss.rs`) |
| Слежение за папками | отдельный поток раз в секунду сравнивает имена, время изменения и размер файлов; изменилась тема — обновляются стили, появился или пропал файл — пересобирается меню трея; настройки на странице узнают об этом через `__arachnidDesktop.extensionsChanged()` |
| Раздел настроек | `settings.js` (второй скрипт инициализации, после моста) находит настройки for-web по устойчивым классам `settings_sidebar` / `settings_cont` и тексту, а не по генерируемым именам классов; пункт «Плагины» ставится после «Внешнего вида» (узнаётся по значку palette, а если значок изменится — по месту в списке) и копирует его разметку, поэтому выглядит как родной. Данные — команды `extensions_overview`, `extensions_set_theme`, `extensions_set_theme_value`, `extensions_reset_theme`, `extensions_set_plugin` (с `grant: true` — после согласия в окне разрешений), `extensions_set_plugin_value`, `extensions_reset_plugin`, `extensions_open`, `extensions_quick_css`, `extensions_set_quick_css` |
| Редактор QuickCSS | Окно — элемент в `#floating` (там же for-web держит свои диалоги) поверх окна настроек; оформлено по Dialog for-web (Material 3). Текст читается командой `extensions_quick_css`, сохраняется `extensions_set_quick_css` (запись через временный файл, затем `setStyles`). Нажатия клавиш не выходят за окно, чтобы Esc не закрывал заодно настройки. Пункт трея вызывает `__arachnidDesktop.openQuickCss()`, сохранение файла другой программой — `quickCssChanged()` |
| Плагины | после загрузки страницы клиента (`on_page_load`, событие `Finished`) каждый включённый плагин выполняется отдельным скриптом, как `executeJavaScript` у Avia: сначала встроенные, затем свои. Плагин-файл — в глобальной области страницы; код плагина-папки — тело асинхронной функции с объектом `plugin` (`bridge.js`, `__arachnidDesktop.plugin`). Ошибка в одном плагине не мешает остальным. Метка на `window` не даёт выполнить плагины дважды в одном документе |
| Файлы папок | схема `arachnid` (`http://arachnid.localhost/` в Windows): `…/plugins/<id>/<путь>` и `…/themes/<id>/<путь>`. Отдаются только файлы внутри папки с манифестом (без `..`, ссылок наружу и файлов больше 64 МБ); относительные `url()` в стилях папки клиент переписывает на эти адреса |
| Плагины-папки | команды `plugin_storage_get`, `plugin_storage_set`, `plugin_fetch`, `plugin_native_call` (`plugin_host.rs`) проверяют, что плагин включён, а адрес запроса — среди подтверждённых; настройки — `extensions_set_plugin_value`, `extensions_reset_plugin`, изменения доходят до страницы через `__arachnidDesktop.pluginSettingsChanged` |
| Отладка | у кода плагина есть подпись `//# sourceURL=arachnid-plugins/<файл>` (у плагина-папки — `arachnid-plugins/<id>/main.js`), поэтому ошибки в консоли разработчика указывают на файл плагина |
| `window.AviaMenu` | мост даёт объект с тем же API, что `avia_core/menu.js`: `register`, `submenuregister`, `submenu`, `updatesubmenu`, `unregister`, с теми же проверками и сообщениями об ошибках. Пункты уходят в Rust командой `set_plugin_menu` и показываются в трее в разделе «Действия плагинов»; выбор пункта показывает окно и вызывает `onClick` плагина |

Плагины выполняются только на странице веб-клиента (адрес из `config.toml`). Сам
код плагина не получает доступа к командам оболочки сверх того, что есть у
страницы.

## Плагины Avia Client

Формат плагинов Avia: обычный скрипт (как правило, IIFE с меткой на `window`),
который хранит настройки в `localStorage`, встраивает кнопки в интерфейс через
`MutationObserver` и при необходимости оборачивает `fetch` или `WebSocket`.
Особого API хоста ему не нужно, кроме меню `window.AviaMenu`, которое здесь есть.

Каталог плагинов сообщества — [PluginRepo](https://avalilac.github.io/PluginRepo/);
у каждого плагина есть кнопка View source со ссылкой на файл. Чтобы установить
плагин:

1. Откройте ссылку на исходник (`raw.githubusercontent.com/…/Plugin.js` или
   `codeberg.org/…/raw/…/Plugin.js`) и сохраните файл в `plugins/`.
2. Прочитайте код (см. «Безопасность» ниже).
3. В настройках: «Плагины» → включите переключатель и
   нажмите «Перезагрузить» (или в трее: «Расширения → Плагины»).

При разработке проверено в jsdom на коде плагинов из PluginRepo: `NotificationPings` и `Auto Capitalize`
регистрируют свои пункты через `AviaMenu`, и переключатель `Auto Capitalize`
меняет подпись через `updatesubmenu`. `KlipyV2` добавляет «Set API Key» тем же
способом.

Часть возможностей Avia — модули самого клиента, а не плагины (например,
панель избранного `avia_core/aviafavsystem.js`). Те из них, что не зависят от
остального Avia, ставятся так же, как плагины: см.
[avia-setup-windows.md](avia-setup-windows.md).

**Чего нет.** Встроенного каталога и автообновления плагинов: заголовок
`@UPDATEURL` клиент не читает, новую версию плагина нужно сохранить поверх
старой. Значки пунктов `AviaMenu` (поле `icon`, имена Material Symbols) в меню
трея не показываются: системное меню выводит только текст.

Название, автор, версия и описание плагина в разделе «Плагины» берутся из
первого комментария файла, если в нём есть `@name` (как у плагинов
BetterDiscord и Vencord):

```js
/**
 * @name Translate
 * @author AvaLilac
 * @version 1.2
 * @description Перевод сообщений
 */
```

Без такого комментария показывается имя файла.

## Плагины-папки

Плагину, которому мало одного файла, — папка в `plugins/`. Имя папки —
идентификатор плагина: латиница, цифры, `-`, `_`, `.` (до 64 символов). В ней
манифест `plugin.toml` и всё, что нужно плагину:

```
plugins/translator/
├── plugin.toml
├── main.js          код страницы (по умолчанию)
├── style.css        стили, пока плагин запущен (по умолчанию)
├── native.wasm      нативный модуль WebAssembly (по умолчанию)
└── img/flag.png     любые свои файлы
```

```toml
name = "Переводчик"          # обязательно
version = "1.0.0"
author = "Ava"
description = "Переводит сообщения"
# main = "main.js"           # свои пути к файлам — внутри папки
# style = "style.css"
# native = "native.wasm"

[permissions]
# адреса, к которым плагин делает запросы: точный адрес или *.домен
network = ["api.example.com", "*.deepl.com"]

[[settings]]
name = "language"
label = "Язык перевода"
type = "select"
default = "ru"
options = [{ value = "ru", label = "Русский" }, { value = "en", label = "English" }]

[[settings]]
name = "auto"
label = "Переводить сразу"
type = "checkbox"
default = true
```

Нужен хотя бы один из `main`, `style`, `native`. Типы настроек — те же, что у
тем (`text`, `color`, `checkbox`, `select`, `number`, `range` с `min`, `max`,
`step`, `unit`); в разделе «Плагины» они в окне под шестерёнкой плагина. В
`style.css` значения доступны переменными `--<имя>`, относительные `url()`
ведут в папку плагина. Новый плагин-папка выключен, как и плагин-файл.

**Разрешения.** Если в `[permissions] network` есть адреса, при включении
клиент показывает их и спрашивает согласия; без него плагин не включится. Если
новая версия плагина попросит больше адресов, до нового согласия ей доступны
только уже подтверждённые (раздел «Плагины» показывает «Ждёт разрешения»).
Запросы — только `https`, без переадресаций (ответ 3xx возвращается как есть).

### API `plugin`

Код `main.js` выполняется как тело асинхронной функции: можно сразу писать
`await`, переменные не попадают в глобальную область страницы. Объект `plugin`:

| Что | Описание |
|---|---|
| `plugin.id`, `plugin.apiVersion` | идентификатор (имя папки) и версия API (сейчас `1`) |
| `plugin.manifest` | `{ name, version, author, description }` |
| `plugin.settings` | значения настроек: флажок — `true`/`false`, число — число, остальное — строка |
| `plugin.onSettingsChange(fn)` | `fn(settings)` при изменении в разделе «Плагины»; возвращает функцию отписки |
| `plugin.storage.get(key)` / `.set(key, value)` / `.delete(key)` | своё хранилище JSON (до 8 МБ, `plugin-data/<id>/storage.json`), общее с нативным модулем; всё возвращает `Promise` |
| `plugin.asset(path)` | адрес своего файла: `img.src = plugin.asset("img/flag.png")` |
| `plugin.network` | подтверждённые адреса |
| `plugin.fetch(url, { method, headers, body, responseType })` | запрос мимо CORS страницы к подтверждённому адресу; ответ `{ status, headers, body }`, тело — текстом или в Base64 (`responseType: "base64"`) |
| `plugin.native.available`, `plugin.native.call(name, input)` | есть ли `native.wasm`; вызов его функции: вход и результат — JSON |

Ошибки команд приходят как `Error` с полем `kind` (`permissions`, `network`,
`native`, `storage`, `plugin`).

```js
// main.js
const button = document.createElement("button");
button.style.backgroundImage = `url(${plugin.asset("img/flag.png")})`;
plugin.onSettingsChange((settings) => console.log("язык:", settings.language));
const response = await plugin.fetch("https://api.example.com/translate", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ text: "hello", to: plugin.settings.language }),
});
const words = await plugin.native.call("count_words", { text: response.body });
```

### Нативный модуль (WebAssembly)

Тяжёлую работу (разбор, сжатие, криптография) плагин может делать в модуле
`native.wasm`, собранном из Rust, C, Zig или AssemblyScript под
`wasm32-unknown-unknown`. Модуль приносят уже собранным — компилятор у
пользователя не нужен. Клиент выполняет его интерпретатором
[wasmi](https://github.com/wasmi-labs/wasmi) в песочнице: у модуля нет доступа
к файлам, процессам и сети, кроме функций клиента ниже. Память — до 256 МБ,
вызов — до нескольких секунд работы (дальше модуль останавливается и при
следующем вызове загружается заново). Модуль загружается при первом вызове;
сохранённый новый файл подхватывается сам.

Договор:

- модуль экспортирует `memory` и `arachnid_alloc(len: i32) -> i32` — буфер под
  входные данные и ответы клиента;
- `plugin.native.call("имя", вход)` кладёт вход (JSON, UTF-8) в буфер и вызывает
  экспорт `имя(ptr: i32, len: i32) -> i32`; `0` — успех, иначе ошибка.
  Результат (JSON) или текст ошибки модуль отдаёт функцией `output`; без неё
  результат — `null`. Экспорты `arachnid_*` со страницы не вызываются;
- функции клиента — модуль импорта `arachnid`:

| Функция | Что делает |
|---|---|
| `log(level, ptr, len)` | строка в журнал клиента: 0 — ошибка, 1 — предупреждение, 2 — сведения, иначе — отладка |
| `output(ptr, len)` | результат вызова |
| `storage_get(key_ptr, key_len) -> i64` | значение ключа (JSON) или `-1` |
| `storage_set(key_ptr, key_len, value_ptr, value_len) -> i32` | записать JSON; `0` — записано |
| `storage_delete(key_ptr, key_len) -> i32` | удалить ключ |
| `fetch(ptr, len) -> i64` | запрос JSON как у `plugin.fetch` (`{ url, method, headers, body, responseType }`), ответ JSON `{ status, headers, body }` или `{ error }` |

Буфер с ответом клиента (его память выделяет `arachnid_alloc` модуля) приходит
упакованным в `i64`: `ptr << 32 | len`.

Пример на Rust (`cargo build --release --target wasm32-unknown-unknown`, в
`Cargo.toml` — `crate-type = ["cdylib"]`, `serde_json`):

```rust
use std::alloc::{alloc, Layout};

#[link(wasm_import_module = "arachnid")]
unsafe extern "C" {
    fn output(ptr: *const u8, len: usize);
}

#[unsafe(no_mangle)]
pub extern "C" fn arachnid_alloc(len: usize) -> *mut u8 {
    // буфер отдаётся модулю навсегда: для коротких вызовов этого достаточно
    unsafe { alloc(Layout::from_size_align(len.max(1), 1).unwrap()) }
}

fn reply(value: &serde_json::Value) -> i32 {
    let text = value.to_string();
    unsafe { output(text.as_ptr(), text.len()) };
    0
}

#[unsafe(no_mangle)]
pub extern "C" fn count_words(ptr: *const u8, len: usize) -> i32 {
    let input = unsafe { std::slice::from_raw_parts(ptr, len) };
    let Ok(input) = serde_json::from_slice::<serde_json::Value>(input) else {
        return 1;
    };
    let text = input["text"].as_str().unwrap_or_default();
    reply(&serde_json::json!({ "words": text.split_whitespace().count() }))
}
```

Рабочий пример на WAT (текстовый WebAssembly) — модуль плагина проверки
`apps/desktop/src-tauri/e2e/plugins/e2e-folder/native.wat`.

## Темы

Подойдёт любой CSS для веб-клиента Stoat, в том числе темы Avia и темы с
[rvlt.gg/discover/themes](https://rvlt.gg/discover/themes): сохраните CSS в
`themes/имя.css` и выберите в «Внешнем виде». Для быстрых правок удобнее QuickCSS.

for-web задаёт цвета переменными (`--md-sys-color-*`, `--colours-*`) прямо в
атрибуте `style` у `body`, поэтому тема, которая меняет эти переменные, должна
ставить `!important`.

### Настройки темы

Тема может описать свои настройки в заголовке
[UserCSS](https://github.com/openstyles/stylus/wiki/Writing-UserCSS) — тот же
формат, что у расширения Stylus и сайта userstyles.world. Тогда в «Внешнем виде»
у неё появляются свои палитры, цвета и переключатели:

```css
/* ==UserStyle==
@name        Ночь
@author      я
@version     1.0.0
@description Тёмная тема с акцентом
@var select   palette  "Палитра"    ["dark:Тёмная*", "oled:OLED"]
@var color    accent   "Акцент"     #cba6f7
@var checkbox blur     "Размытие"   1
@var range    radius   "Скругление" [12, 0, 24, 1, "px"]
@var text     font     "Шрифт"      "Inter"
==/UserStyle== */

body {
  --md-sys-color-primary: var(--accent) !important;
  font-family: var(--font), sans-serif;
}
```

| Тип | Элемент в настройках | Значение |
|---|---|---|
| `text` | поле ввода | строка |
| `color` | образец цвета и поле | любой цвет CSS |
| `checkbox` | флажок | `1` или `0` |
| `select`, `dropdown`, `image` | выпадающий список; `*` — вариант по умолчанию | значение варианта |
| `number`, `range` | число или ползунок: `[по умолчанию, мин, макс, шаг, "единица"]` | число с единицей |

Как значения попадают в CSS:

- **По умолчанию** (`@preprocessor default` или без него) — переменными в
  `:root`: `--palette`, `--accent`, `--radius: 12px` и т. д.
- **`@preprocessor uso`** — заменой `/*[[имя]]*/` в тексте темы. Так удобно
  держать палитры: у каждого варианта `dropdown` свой кусок CSS
  (`@advanced dropdown palette "Палитра" { dark "Тёмная*" <<<EOT … EOT; }`).
- `@preprocessor less` и `stylus` требуют компилятора: тема подключается как
  есть, а «Внешний вид» предупреждает, что её настройки не применяются.

Секции `@-moz-document`, подходящие к адресу веб-клиента, раскрываются (их
Chromium не понимает), остальные отбрасываются. Значения хранятся в
`extensions.json` отдельно для каждой темы и переживают обновление файла темы;
«Сбросить настройки темы» возвращает значения из заголовка.

Тема без `==UserStyle==` тоже работает, просто без своих настроек; название и
автор берутся из первого комментария с `@name`, как у тем BetterDiscord.

### Темы-папки

Теме со своими картинками и шрифтами — папка в `themes/` с `theme.toml`:

```toml
name = "Ночь"
version = "1.0.0"
author = "я"
# main = "theme.css"   # по умолчанию

[[settings]]
name = "accent"
label = "Акцент"
type = "color"
default = "#cba6f7"
```

Настройки — как у плагинов-папок, в CSS — переменными `--<имя>`. Относительные
адреса (`url(fonts/inter.woff2)`, `url("img/bg.png")`) ведут в папку темы.

## Безопасность

Плагин выполняется с теми же правами, что и сама страница: он видит сессию и
может отправлять запросы от вашего имени. Поэтому:

- читайте код плагина перед включением (в PluginRepo встречаются плагины,
  которым нужен ваш токен, — например, `Gradient roles`);
- не включайте плагины пачкой — так проще найти тот, что сломался после
  обновления Stoat;
- не вводите пароль или токен в окна плагинов, кроме явно нужных (например,
  ключ API Klipy для `KlipyV2`).

Разрешения плагинов-папок — это согласие на конкретные адреса, а не
песочница для их кода на странице: `main.js`, как и плагин-файл, выполняется
на странице с её правами. Песочница есть у нативного модуля: ему доступно
только то, что дают функции клиента.

Если клиент перестал открываться из-за плагина, выключите его в трее (или в
разделе «Плагины») либо удалите файл или папку из `plugins/`. Выключить все сразу: закройте клиент (трей →
«Выйти из приложения») и удалите `extensions.json`.
