# Как устроена оболочка

Arachnid Client устроен так же, как официальный
[Stoat for Desktop](https://github.com/stoatchat/for-desktop): окно открывает веб-клиент
Stoat с сервера инстанса, а оболочка даёт ему то, чего нет у браузера.
Разница в том, что оболочка написана на Rust (Tauri 2), а вместо встроенного
Chromium используется системный webview: WebView2 в Windows, WebKitGTK в Linux,
WKWebView в macOS.

```
┌──────────────── окно Tauri (WebView2) ─────────────────┐
│  https://stoat.chat/app — for-web без изменений        │
│        │ window.native / window.desktopConfig          │
│        ▼                                               │
│  bridge.js (скрипт инициализации, до скриптов страницы)│
│  settings.js (раздел «Плагины», выбор темы, подпись)   │
│  defaults.js (Twemoji по умолчанию)                    │
│  emoji.js (разделы и частые в выборе эмодзи)           │
│  emoji_packs.js (скачивание наборов в шторке выбора)   │
└────────│───────────────────────────────────────────────┘
         │ IPC Tauri (только адрес клиента, только окно main)
         ▼
  desktop.rs: окно, настройки «ПК», трей, автозапуск, Discord RPC
  extensions.rs + usercss.rs: темы и их настройки, QuickCSS, плагины
                              (docs/extensions.md)
  memory.rs: экономия памяти WebView2, пока окно в фоне
  icon.rs: чёткие значки окна и трея из ресурса exe (Windows)
  media.rs: микрофон, камера и звук для клиента без запросов (Windows)
  emoji_packs.rs + http.rs: наборы эмодзи без static.stoat.chat — Twemoji
                            из exe, остальные скачиваются (Windows)
  system_emoji.rs: Fluent Color и Flat из шрифта Windows 11, без скачивания
```

## Договор с веб-клиентом

for-web проверяет `window.native`. Если объект есть, он показывает свою строку
заголовка, раздел настроек «ПК» и версии оболочки (`Native.tsx`, `Titlebar.tsx`,
`UserSettings.tsx`). Stoat for Desktop отдаёт эти объекты из preload-скрипта
(`src/world/window.ts`, `src/world/config.ts`); `src/bridge.js` повторяет тот же
договор поверх команд Tauri:

| for-web вызывает | Команда Rust | Что делает |
|---|---|---|
| `native.minimise()` | `native_minimise` | свернуть окно |
| `native.maximise()` | `native_maximise` | развернуть или вернуть размер |
| `native.close()` | `native_close` | закрыть: проходит через «Сворачивать в трей» |
| `native.versions.*()` | — | версии подставлены в скрипт при создании окна |
| `desktopConfig.get()` | — | синхронно, из подставленных настроек |
| `desktopConfig.set(patch)` | `desktop_config_set` | сохранить в `desktop.json`, включить или выключить Discord RPC |
| `desktopConfig.getAutostart()` | `desktop_autostart_get` | включён ли автозапуск |
| `desktopConfig.setAutostart(v)` | `desktop_autostart_set` | включить или выключить, вернуть итог |

Команды самого моста (их вызывает `bridge.js`, а не for-web):

| Команда | Что делает |
|---|---|
| `set_tray_labels` | подписи меню трея на языке системы (русские или английские) |
| `extensions_styles` | включённые темы и QuickCSS при загрузке страницы |
| `set_plugin_menu` | пункты `window.AviaMenu` для раздела «Действия плагинов» в трее |

Команды раздела настроек (`settings.js`):

| Команда | Что делает |
|---|---|
| `extensions_overview` | темы с их настройками и значениями, плагины, нужна ли перезагрузка |
| `extensions_set_theme` | выбрать тему или `null` — стандартное оформление Stoat |
| `extensions_set_theme_value` | изменить настройку темы (`null` — по умолчанию) |
| `extensions_reset_theme` | сбросить все настройки темы |
| `extensions_set_plugin` | включить или выключить плагин (страница не перезагружается сама) |
| `extensions_open` | открыть папку тем, плагинов или `quickcss.css` во внешней программе |
| `extensions_quick_css` | текст `quickcss.css` для редактора (заготовка, если файла нет) |
| `extensions_set_quick_css` | сохранить QuickCSS из редактора и сразу применить |

В обратную сторону Rust вызывает `window.__arachnidDesktop`: `update(config)`
(новые настройки), `setStyles(styles)` (сохранили тему), `runMenuItem(id)`
(выбрали пункт плагина в трее), `extensionsChanged()` (темы или плагины
изменились из трея или в папке — раздел настроек перечитывает их),
`openQuickCss()` (пункт трея «Изменить QuickCSS») и `quickCssChanged()`
(`quickcss.css` сохранили в другой программе).

`native.versions` for-web выводит внизу списка настроек как «Stoat for Desktop
0.14.0» и строку `Tauri 2.x, Windows x86_64, WebView 1xx` (поля `electron`,
`node`, `chrome`); `settings.js` заменяет «Stoat for Desktop» на «Arachnid
Client».

### Настройки веб-клиента

`settings.js` встраивает в настройки for-web то, чего в нём нет (подробно — в
[extensions.md](extensions.md#настройки-клиента)):

- раздел «Плагины» в «Настройках клиента» между «Внешним видом» и
  «Уведомлениями» (там, где у for-web закомментирован свой пункт plugins);
- кнопки «Папка тем» и «Изменить QuickCSS» (окно-редактор) и выбор темы в «Внешнем виде» вместо
  приветствия «Welcome to the new appearance menu…»; при сторонней теме блок
  «Цвета» Stoat заменяется настройками темы;
- подпись «Arachnid Client» вместо «Stoat for Desktop».

`emoji.js` дополняет окно выбора эмодзи, как в Discord: в колонке слева вверху —
«Часто используемые» и быстрый переход к стандартным эмодзи, под серверами —
разделы «Люди», «Природа», «Еда и напитки», «Путешествия и места», «Занятия»,
«Предметы», «Символы», «Флаги» (видимый раздел подсвечивается); над сеткой —
блок «Часто используемые» (до двух строк, и стандартные эмодзи, и эмодзи
серверов; счётчики — в `localStorage`, свои у каждого аккаунта). Щелчок по
частому эмодзи передаётся ячейке for-web, поэтому он работает и в поле
сообщения, и в реакциях. Разделы — группы Unicode в порядке списка for-web
(`emojiMapping.json`): начало раздела задано номером его первого эмодзи и
после прокрутки сверяется с отрисованной ячейкой. Подробности опор — в
комментарии в начале скрипта.

Пока окно открыто, список for-web перерисовывается на каждом кадре прокрутки,
поэтому скрипт ничего не делает в ответ на сами перерисовки: окно ищется
только там, где в документ добавлено поле ввода (и не чаще раза в кадр), а
размеры сетки для подсветки раздела запоминаются и перечитываются лишь при
изменении её размеров (`ResizeObserver`). Раньше каждое изменение документа
запускало поиск окна по всему документу — прокрутка тормозила тем сильнее,
чем больше открытый канал.

Исходники for-web изменить нельзя (страница грузится с сервера), а имена
классов Panda CSS меняются от сборки к сборке. Поэтому скрипт опирается только
на устойчивое: классы `settings_sidebar` и `settings_cont`, значки пунктов
(palette у «Внешнего вида», `desktop_windows` у «ПК») и тексты, а разметку
пунктов и полей копирует у соседних элементов for-web. Открытую страницу
for-web отмечает классом варианта Panda (атрибут `aria-selected` до разметки
не доходит), поэтому выбранный пункт определяется по классу, отличному от
остальных. `MutationObserver` следит за открытием настроек и
переходами между разделами; если for-web изменит разметку так, что опора не
найдётся, скрипт просто ничего не добавляет.

`desktopConfig.get()` должен быть синхронным: for-web читает его при отрисовке.
Поэтому Rust подставляет текущие настройки прямо в скрипт при создании окна, а
последнее состояние скрипт держит в `sessionStorage` вкладки, чтобы перезагрузка
страницы (F5) не возвращала старые значения. Изменения, сделанные не со
страницы (окно развернули системной кнопкой или перетаскиванием к краю),
Rust передаёт в `window.__arachnidDesktop.update(...)`.

### Значения по умолчанию

| Настройка | Stoat for Desktop | Arachnid Client |
|---|---|---|
| Discord RPC | включён | **выключен**: статус в Discord включает сам пользователь в разделе «ПК» |
| Набор эмодзи | Fluent 3D | **Twemoji** |
| Микрофон, камера, звук | без запросов (Electron) | без запросов (см. [ниже](#нативное-что-даёт-сам-webview)) |

Discord RPC выключен в `DesktopConfig::default()`: это касается первого запуска
и `desktop.json` без этого поля, а уже сохранённый выбор остаётся.

Набор эмодзи for-web хранит в браузерном хранилище, а не на сервере:
IndexedDB `localforage`, ключ `settings`. Хранилище зависит от версии for-web:

- `keyvaluepairs` — общее хранилище localforage. Так хранят выпущенные версии
  (stoat-for-web-v0.16.x — то, что открывается на stoat.chat/app);
- `@<id пользователя>` — по хранилищу на аккаунт; так хранит for-web с
  переключением аккаунтов (пока только в его `main`, не выпущено).

`defaults.js` поддерживает обе раскладки. for-web читает настройки один раз —
при загрузке страницы (и при переключении аккаунтов), а записывает, только
когда они меняются. `defaults.js` записывает туда `twemoji`, если набор не
выбран или стоит значение for-web по умолчанию fluent-3d, — один раз для
каждого хранилища (отметка `arachnid:defaults:<хранилище>` в `localStorage`),
поэтому выбранный потом в настройках набор, в том числе Fluent 3D, остаётся.
Запись всегда успевает до чтения:

- хранилища, которые уже есть, — при загрузке страницы, все сразу. Скрипт
  выполняется до скриптов страницы, его запрос открытия базы встаёт в очередь
  раньше запроса for-web, а IndexedDB выполняет их по порядку;
- новое хранилище (первый запуск, добавленный аккаунт) — когда localforage его
  создаёт: настройки с Twemoji кладутся в той же транзакции обновления базы
  (`IDBDatabase.createObjectStore` в базе `localforage`), так что for-web
  читает их сразу, без перезапуска.

### Наборы эмодзи

for-web рисует каждый стандартный эмодзи картинкой
`https://static.stoat.chat/emoji/<набор>/<кодовые точки>.svg?v=1` (адрес
зашит в `UnicodeEmoji.tsx`, см. [for-web#1356](https://github.com/stoatchat/for-web/issues/1356)).
Пока картинка не пришла, на месте эмодзи пусто; новый набор после выбора в
настройках скачивается заново, по картинке на эмодзи. Если до static.stoat.chat
связь медленная (в России Stoat заблокирован), эмодзи и выбор набора появляются
с большой задержкой.

Поэтому картинки отдаёт сам клиент. `emoji_packs.rs` (Windows) подписывается на
`WebResourceRequested` WebView2 для `https://static.stoat.chat/emoji/<набор>/*`
и отвечает картинкой из файла набора, если набор есть у клиента, — эмодзи
появляются сразу и без сети. Если набора у клиента нет или в нём нет картинки,
клиент берёт её с того же сервера, что и официальный клиент
(`Server-Timing: arachnid;desc="network"`).

Странице картинка уходит **растром PNG**, а не SVG (`emoji_raster.rs`). В
Chromium (и WebView2) каждая картинка SVG — отдельный документ со своим
планировщиком задач, и он живёт в кэше памяти и после того, как его `<img>`
ушёл со страницы. После каждой задачи главного потока Blink обходит все такие
планировщики (crbug.com/582923445), так что цена любой задачи растёт с числом
уже показанных эмодзи. Окно выбора эмодзи for-web — виртуальный список: в DOM
только видимые картинки, но при прокрутке каждая новая картинка оставляла свой
документ, и окно тормозило всё сильнее. Замеры: кадр прокрутки — с 28 до 110 мс
к концу списка; пустая задача в WebView2 после 1100 эмодзи — 6,5 мс вместо
0,01. С PNG документов нет, цена задачи постоянная (проверяет e2e).

- SVG наборов рисует resvg, слои системного шрифта — tiny-skia (из того же
  resvg), без текста и системных шрифтов. Fluent 3D — PNG, завёрнутый в SVG:
  его PNG отдаётся как есть. Внешние файлы из SVG не читаются.
- Сторона картинки — под самый крупный эмодзи for-web (96 px, сообщение из
  одного эмодзи) с учётом самого крупного масштаба среди экранов; в окне выбора
  и в тексте браузер её уменьшает.
- Рисование идёт в фоновых потоках (не больше четырёх; последняя просьба
  рисуется первой — при быстрой прокрутке сначала то, что видно), ответ
  странице откладывается (deferral WebView2) до готовой картинки. Нарисованные
  картинки остаются в памяти (до 32 МБ, первыми уходят давно не нужные), так что
  прокрутка туда и обратно не рисует их заново. Картинки с сервера берутся в
  отдельных потоках (до 16 сразу), так что ожидание сети не задерживает
  рисование того, что есть у клиента; запросы идут через одну сессию WinHTTP с
  HTTP/2 — по одному переиспользуемому соединению.

- **Twemoji** (набор по умолчанию) встроен в exe: `emoji/twemoji.bin`, SVG из
  [jdecked/twemoji](https://github.com/jdecked/twemoji) той же версии, что у
  официального набора Stoat (подмодуль `packs/twemoji` в
  [stoatchat/javascript-genemoji](https://github.com/stoatchat/javascript-genemoji)),
  4009 картинок, около 4 МБ.
- **Fluent 3D, Fluent Color, Fluent Flat, Mutant Remix, Noto** скачиваются и
  удаляются прямо в шторке выбора набора («Настройки» → «Внешний вид» →
  «Emoji Pack», `emoji_packs.js`). Справа у каждого пункта: у Twemoji —
  «Встроен», у не скачанного набора — размер и кнопка «Скачать», во время
  скачивания — кольцо с процентами и «Отмена», у скачанного — «Скачан» и
  «Удалить», после ошибки — «Ошибка» (причина в подсказке) и «Повторить».
  Кнопки не выбирают набор, щелчок по остальному пункту выбирает его, как
  обычно. Не скачанный набор, как и в браузере, грузится картинками с
  сервера. Добавленное живёт в теневом DOM пункта: подпись поля выбора и
  стили for-web не меняются. Файлы лежат в папке `emoji/` каталога данных (`<набор>.bin`); скачивание идёт
  во временный `<набор>.bin.part`, который подключается только после проверки
  размера (по `manifest.json`) и оглавления. Загрузка — WinHTTP (`http.rs`):
  системный HTTP-стек с прокси из настроек Windows, без отдельной TLS-библиотеки
  в exe.
- **Fluent Color и Fluent Flat** в Windows 11 уже есть: это эмодзи системного
  шрифта Segoe UI Emoji (`system_emoji.rs`). Если шрифт их рисует, набор в
  шторке помечен «В системе», кнопки «Скачать» у него нет, а картинки клиент
  рисует из шрифта сам (`Server-Timing: arachnid;desc="system"`).
  - Что есть в системе, решает сам шрифт, а не номер версии Windows: нужна
    таблица COLR версии 1 и у 😀 — слои нужной версии. Fluent Color — слои
    COLRv1 с градиентами, Fluent Flat — плоские слои COLRv0 из того же шрифта.
    В Windows 10 и в Windows 11 до обновления шрифта (2023) таких слоёв нет, там
    наборы скачиваются, как остальные.
  - **Fluent 3D** в Windows нет: в шрифте нет объёмных растровых рисунков, этот
    набор скачивается и в Windows 11.
  - Кодовые точки адреса картинки превращаются в глиф шрифта через harfrust
    (ZWJ, оттенки кожи и keycap — лигатуры шрифта), слои глифа (read-fonts)
    рисуются сразу в растр tiny-skia: контуры — пути, цвета палитры и
    градиенты (линейный, радиальный, угловой), режимы наложения COLR — режимы
    tiny-skia, обрезки — маски.
  - Флагов стран в Segoe UI Emoji нет: их картинки идут с сервера, как без
    шрифта. Скачанная раньше копия набора главнее шрифта, пока её не удалят.
  - Шрифт отображается в память только для чтения и читается при первом
    обращении к наборам.

Файлы скачиваемых наборов — пре-релиз
[`emoji-packs-v1`](https://github.com/sssHpion007/Arachnid-Client-Stoat/releases/tag/emoji-packs-v1).
Его собирает `.github/workflows/emoji-packs.yml`: `emoji/fetch.mjs` скачивает с
static.stoat.chat те же картинки, что показывает for-web (все эмодзи из
`data/emoji-test.txt` genemoji и всё, что есть в Twemoji: genemoji подставляет
Twemoji туда, где у набора своей картинки нет), `emoji/pack.mjs` упаковывает их.
Номер в названии релиза — версия формата файла.

Формат файла набора описан в начале `emoji/pack.mjs`: оглавление с ключами по
возрастанию и картинки, каждая сжата Brotli отдельно. Формы записи с селектором
варианта `fe0f` и без него — одна картинка, как у genemoji. Скачанный набор не
читается в память целиком: в памяти только оглавление, картинка читается с
диска по запросу. В Linux и macOS все картинки идут с сервера.

Ответ клиента помечен заголовком `Server-Timing: arachnid;desc="builtin"`
(или `"downloaded"`): в DevTools видно, какие картинки отдал клиент.

Фильтр `WebResourceRequested` должен быть добавлен до перехода на страницу,
иначе WebView2 не показывает обработчику запросы service worker (у for-web он
есть). Поэтому в Windows окно открывается с `about:blank`, затем подключаются
обработчики WebView2 (наборы эмодзи, микрофон и камера) и только после этого
окно переходит на веб-клиент.

Всё это проверяется на собранном exe в настоящем WebView2 — задача
«проверка в WebView2» в `windows.yml`, см. [build.md](build.md#проверка-в-webview2).

### Чего нет в договоре и почему

- `onceScreenPicker` / `screenPickerCallback`: for-web использует их, только если
  они есть. Без них демонстрацию экрана выбирает WebView2 своим окном выбора.
- `isWayland`: нужен только Linux-сборке Electron.
- `setBadgeCount` и `onNavigate`: есть в Stoat for Desktop, но for-web их не вызывает.

## Права

Страница загружена с удалённого адреса, а такой странице Tauri разрешает только
команды, на которые есть право. `build.rs` перечисляет команды моста, и Tauri
создаёт для них права `allow-…`. При запуске `lib.rs` выдаёт их capability
`web-client`, привязанной к адресу из `config.toml` (`https://stoat.chat/*`) и к
главному окну. Ни у какой другой страницы доступа к командам нет.

## Окно

- **Адрес.** `config.toml` → `[instance] app_url`, по умолчанию
  `https://stoat.chat/app` (как у Stoat for Desktop без `--force-server`). Только
  https; http разрешён для localhost (разработка своего инстанса).
- **Переходы.** Как `will-navigate` в Stoat for Desktop: окно не уходит с origin
  веб-клиента. `window.open` (ссылки с `target="_blank"`) открывает http, https и
  mailto в системе, новое окно не создаётся.
- **Рамка.** `customFrame` убирает системную рамку при запуске; кнопки и
  перетаскивание даёт строка заголовка for-web (`-webkit-app-region: drag`,
  WebView2 понимает её сам). Как и в Stoat for Desktop, смена рамки действует
  после перезапуска.
- **Аппаратное ускорение.** При выключенном WebView2 запускается с `--disable-gpu`
  (после перезапуска).
- **Проверка орфографии.** У WebView2 нет переключателя, как
  `session.setSpellCheckerEnabled` в Electron, поэтому при выключенной настройке
  мост ставит полям ввода `spellcheck="false"` и возвращает исходное значение при
  включении. Подсказки и «Добавить в словарь» — в стандартном контекстном меню.
- **Профиль webview** (`webview/` в каталоге данных): вход, `localStorage`, кэш.
  В portable-режиме лежит рядом с exe, поэтому папку можно переносить с входом.
- **Перетаскивание файлов.** Системный обработчик Tauri выключен
  (`dragDropEnabled: false`), чтобы работало HTML5-перетаскивание вложений в чат.
- Фон окна `#191919` до загрузки страницы, минимальный размер 300×300, как у
  Stoat for Desktop.
- **Значок** (`icon.rs`, Windows). Tauri ставит окну одну картинку — первый кадр
  `icon.ico` — и только как малый значок, а для панели задач и Alt+Tab Windows
  растягивает её же. Поэтому малый и большой значки окна и значок трея берутся
  из ресурса exe (tauri-build вшивает туда `icons/icon.ico` со всеми кадрами:
  256, 64, 48, 40, 32, 24, 20, 16): `LoadImageW` выбирает кадр точно под размер
  для масштаба монитора, при переезде окна на монитор с другим масштабом значки
  обновляются. Первый кадр `icon.ico` — 256×256, чтобы и запасной значок Tauri
  был чётким.

## Память

Веб-клиент в WebView2 занимает столько же, сколько в браузере. Пока окно не на
экране, `memory.rs` сообщает WebView2 `MemoryUsageTargetLevel = Low`
(`ICoreWebView2_19`): движок сбрасывает кэши и вытесняет неиспользуемое в файл
подкачки, а страница продолжает работать — сообщения, уведомления и звонок не
прерываются, перезагрузки нет. Так же делают Dorion и другие клиенты на WebView2.

- **Когда.** Через 20 секунд после сворачивания или скрытия в трей (быстрое
  «свернуть и вернуть» память не трогает); по желанию — через 2 минуты без
  фокуса. Как только окно показали или оно получило фокус, обычный режим
  возвращается сразу. Окно, запущенное в трее и ещё не показанное, не
  трогается: страница в нём только загружается.
- **Настройка.** `config.toml`:

  ```toml
  [memory]
  background = true   # экономить, пока окно свёрнуто или в трее
  unfocused = false   # ещё и когда окно 2 минуты без фокуса
  ```

- **Ограничения.** Нужен WebView2 Runtime 1.0.1722.45 или новее (на старом
  режим не меняется, в журнале одна запись). В Linux и macOS у webview такого
  режима нет. Принудительных мер вроде приостановки страницы, отключения GPU
  или `EmptyWorkingSet` нет: они либо ломают фоновую работу клиента, либо
  только переносят память в файл подкачки на вид.

## Нативное, что даёт сам webview

Уведомления (Notification API), микрофон и камера, демонстрация экрана
(`getDisplayMedia`), масштаб (Ctrl + колесо, Ctrl + `+` `-` `0`), перезагрузка
(F5, Ctrl + R) и контекстное меню с подсказками орфографии — стандартные
возможности WebView2. Разрешение на уведомления WebView2 спрашивает своим
окном и запоминает в профиле.

Микрофон, камеру и автовоспроизведение со звуком клиент получает без запросов,
как в Stoat for Desktop (`media.rs`, Windows): для origin клиента из
`config.toml` в профиле WebView2 ставится «Разрешено»
(`ICoreWebView2Profile4::SetPermissionState`, это заменяет и случайно нажатое
когда-то «Запретить»), а запросы, дошедшие до события `PermissionRequested`,
одобряются, если пришли с того же origin. Динамикам отдельное разрешение не
нужно. Другие страницы так ничего не получают. Системный переключатель Windows
«Разрешить приложениям доступ к микрофону/камере» остаётся за пользователем. В
Linux и macOS запросы обрабатывает webview системы.
